The Big Picture
The entire DNS wizard boils down to three things: (1) ask the internet who manages a domain's DNS, (2) show the user copy-paste instructions for that specific provider, and (3) keep checking until the DNS records show up. That's literally all this does. No magic, no complex protocols. It's look up, display, and poll.
Think of NS records like asking "who's the landlord of this building?" You ask the internet "who manages DNS for brookeandbelle.com?" and it comes back with something like "ns1.cloudflare.com". You match that against a short list of 6 known providers, and now you know which instructions to show. The user pastes in the records, comes back, and we keep checking every 20-30 seconds until the records appear. When they do, we celebrate. Done.
1
Provider Detection
Figure out where the domain's DNS lives
When someone types "promo.brookeandbelle.com", we need to figure out where their DNS lives. We look up the NS (nameserver) records for the root domain ("brookeandbelle.com"). Node.js has a built-in DNS module that does this in one line. The NS records come back as hostnames like ["ns1.cloudflare.com", "ns2.cloudflare.com"]. We check those against a list of known patterns. Match = we know the provider. No match = show generic instructions. That's all provider detection is.
API Route
POST /api/domains/detect-provider
Key details:
  • Must use Node.js runtime (not Edge) — add export const runtime = 'nodejs' at the top
  • Use dns.promises.resolveNs() to look up nameservers
  • Normalize domain input first — strip https://, paths, ports
  • Use the tldts npm package to extract the registrable domain (handles .co.uk, .com.au, etc.)
  • Match NS records against known patterns (see provider table below)
  • If no match → return "unknown" with generic fallback. Totally fine.
// Return shape { provider: "cloudflare" | "godaddy" | ... | "unknown", providerName: "Cloudflare", confidence: "high" | "medium" | "low", nsRecords: ["ns1.cloudflare.com", "ns2.cloudflare.com"] }

2
The Wizard UI
A modal with 4 steps — data flows forward
The wizard is a modal with 4 steps and a stepper bar at the top. Each step is its own component. One orchestrator component manages which step is active, holds shared state, and passes data down. Data flows forward only: Step 1 detects the provider → Step 2 uses that to show the right instructions → Step 3 polls for verification → Step 4 says congrats.
State the orchestrator tracks
currentStep: 1 | 2 | 3 | 4
domain: string
normalizedDomain: string
detectedProvider: { provider, providerName, confidence }
verificationStatus: { txt: pending | verified, cname: pending | verified }
1
Domain Entry — Text input. User clicks "Look Up My Domain". Calls the detect-provider API. Shows detected provider badge. User clicks Continue.
2
Copy & Paste Instructions — Shows provider-specific instructions. Two DNS record cards (TXT for verification, CNAME for pointing). Each has a copy button. User clicks "I've added the records".
3
Verification — Auto-polls every 20-30s. Shows per-record status (one might verify before the other). When both verify, enables Continue button.
4
Success — Celebration message, verified domain badge, "Done" button closes the modal.

3
Verification Polling
Keep checking until DNS records appear
After the user says "I've added the records," we check if those records actually exist in DNS yet. DNS changes can take 30 seconds to a few hours (usually under 10 minutes). So we poll — keep asking "are they there yet?" on an interval. Each record (TXT and CNAME) is checked independently because one might propagate before the other.
How it works:
  • When Step 3 mounts, start an interval calling POST /api/domains/[id]/verify every 20-30 seconds
  • Show a spinner next to each record while pending, green checkmark when verified
  • After 10-15 minutes with no success, slow the polling and show "taking longer than usual"
  • When both records verify → stop polling, enable Continue, auto-advance to Step 4
  • Clean up the interval on unmount (useEffect cleanup function)
// Verify endpoint response shape { verified: boolean, // true only when ALL records check out recordChecks: [ { type: "TXT", status: "verified" | "pending" | "error" }, { type: "CNAME", status: "verified" | "pending" | "error" } ] }
The existing verify endpoint (app/api/domains/[id]/verify/route.ts) already exists. You may need to extend its response to include the recordChecks array so the UI can show per-record status.

The 6 Provider NS Patterns
This covers ~95% of DTC operator domains
Provider NS Pattern
Cloudflare *.ns.cloudflare.com
GoDaddy *.domaincontrol.com
Namecheap *.registrar-servers.com
Google / Squarespace *.googledomains.com
Route 53 (AWS) *.awsdns-*.*
Vercel DNS *vercel-dns.com
// Simple matching logic const ns = nsRecord.toLowerCase(); if (ns.endsWith('.ns.cloudflare.com')) return 'cloudflare'; if (ns.endsWith('.domaincontrol.com')) return 'godaddy'; if (ns.endsWith('.registrar-servers.com')) return 'namecheap'; if (ns.endsWith('.googledomains.com')) return 'google'; if (ns.includes('.awsdns-')) return 'route53'; if (ns.includes('vercel-dns.com')) return 'vercel'; // else: return 'unknown'

Step 2 — Instructions

Step 3 — Verification
Poll 1 (t+0s):   txt: pending,   cname: pending
